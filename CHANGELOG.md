# Changelog

## Unreleased

### Added

- **The match settings are remembered between visits.** When a match starts, the plain setup options are saved under one new key, `spy_setup_settings`, as `{ version: 1, settings }`: players, spies, timer, categories, difficulty (the array of levels, as `settings.diff` holds it), the card-reveal mode, the hint types, every switch and the emergency-vote limit. They are put back into the setup form at start-up and after "new match" (`restoreSavedSetup` in `ui/setup.js`, called from `main.js` and `RESET_MATCH`), including the chips' pressed look, the emergency-vote box and the number of name inputs. Not saved: the player names (their own key, as before), custom words, language, theme, sound, and `detectiveUsed` (it belongs to the running match). Nothing new is shown on any screen, so no text and no recorded Persian screen changed.
- **What is read back is never trusted** (`sanitizeSetupSettings` in `core/config.js`, used when reading, when writing and when filling the form). Each field is judged on its own and a bad one takes only its own default: a number must be a whole number (else the default) and is clamped to `RULES` (players 3 to 20, timer 1 to 15, emergency votes 1 to 10); spies are clamped to 1 and `getMaxSpiesAllowed(players)` for the restored player count; a switch must be a real boolean; unknown category and hint ids are dropped (an empty result is the default list); difficulty goes through `normalizeDifficulties`, so the single string older data holds is still read and an empty or unknown choice is all three levels; unknown keys are ignored. Text that is not JSON, a record that is not `{ version: 1, settings }`, or a `localStorage` that throws means "nothing to restore": the form stays as it is and the app works with the defaults.
- A resumed match keeps its own settings. `RESTORE_GAME` is untouched, `restoreSavedSetup` only writes the form (never `gameState`) and does nothing while a match is in progress (`isMatchInProgress`), and ending, discarding or resetting a match does not delete the saved setup.

### Changed

- `core/state.js` starts `gameState.settings` from `defaultSetupSettings()` (`core/config.js`) instead of its own literal, so the saved setup falls back to the very same defaults. The values are unchanged.
- **The difficulty setting is now three checkboxes (easy, medium, hard) instead of a list**, styled and wired like the category chips (`.chip-item`, `syncCheckboxChipVisuals`), all ticked by default, in a `<fieldset>` with the existing "Difficulty" label as its legend. Any mix can be chosen (easy + hard, medium + hard, ...). At least one chip always stays ticked: unticking the last one is refused (it stays ticked and a short message, `setup.difficulty.keepOne`, says why); if the form ever reached Start with none ticked, all three are used and ticked again, the same safety net as for the categories. The timer field, which shared a row with the old list, now has its own row (full width above 380 px; nothing changes on a narrow phone, where that row was already one column).
- **`gameState.settings.diff` is now an array of levels** (`['easy', 'medium', 'hard']` by default) instead of `'all' | 'easy' | 'medium' | 'hard'`. `normalizeDifficulties()` in `core/config.js` reads both forms: `'all'` is all three levels, a level name is that level alone, and anything else (garbage, an empty array) is all three, so a match saved by an earlier build restores with the same meaning. `SAVE_VERSION` stays 12: nothing breaks on an old save, and a bump would have thrown away every match in progress. (An older build that opens a save made by this one finds an array it does not know and uses the whole word pool.)
- **The word pool is filtered by the chosen set of levels** in `filterPoolByDifficulty()` (`game/rounds.js`, exported): only built-in words whose rating is chosen are kept, and a custom word is always kept whatever levels are chosen (see the "Custom words ignore the difficulty" entry under Fixed); all three levels leave the pool as it is; a choice that matches no word at all falls back to the unfiltered pool, as before (it cannot happen while the pool holds a custom word); used words are tracked as before.
- Texts: `setup.difficulty.all` ("All levels") is removed (nothing uses it any more); `setup.difficulty.keepOne` is new. The visible text of the difficulty field is the label and the three level names; only the "همه سطوح" line is gone. `tests/e2e/lang-switch.test.mjs` takes that line and the old select out of the EXPECTED data (with guards that each is found exactly once); `persian-baseline.json` is not edited.
- Tests: `tests/unit/difficulty.test.mjs` (the normalizer, every combination of levels on both word banks, legacy strings, garbage, the empty-filter fallback, custom words, used words, and saves from before the chips through the real restore), more cases in `tests/unit/setup.test.mjs` (the form read, the last-chip guard), and `tests/e2e/difficulty-chips.test.mjs` (the named group, 44 px targets at 360 and 320 px in both directions, the look in all 8 themes, a real medium + hard round with the random source pinned, the last chip, a resumed 'hard' save). `startMatch` in `tests/e2e/helpers/play.mjs` takes an optional `levels`.
- The service-worker hash now also covers the `version` of `package.json`, so bumping only the version still produces a new hash, a new service worker and a new cache (installed users would otherwise never receive the new number). The hash of an unchanged project therefore differs from the one of earlier builds once, at this change.
- **A correct word guess is now worth 1, 2 or 3 points on an easy, medium or hard word** (2 for custom words and any word with no rating), instead of a flat 3. `SCORING.SPY_CORRECT_GUESS` is replaced by `SPY_GUESS_BY_DIFFICULTY` and `getSpyGuessPoints()` in `core/config.js`.
- **The guessing spy no longer also collects the round-win points.** A correct guess ends the round for the spy team: the guesser gets only the guess points, every other non-spectator spy (alive or already caught) still gets the round win, and the guesser still counts as a winner in the win statistics.
- The three buttons on the guess screen no longer state point amounts (they depended on a flat rule that no longer exists); a short line under them explains the outcome. The scoring list in the wager help text was updated to match.
- **Broke the import cycles around `dispatch`.** `core/dispatch.js` is now a small port that forwards to a handler; the big action `switch` moved to `app/actions.js`, and `setPhase` / `commitState` moved to `core/phase.js`. `app/wire.js` connects the handler, the screen renderer and the timer's phase-change hook once at start-up (`main.js` calls `wireApp()` first). Game behaviour is unchanged, and `dispatch` and `showInfoModal` are still exported from `core/dispatch.js`. `setPhase` and `commitState` are no longer exported from there; import them from `core/phase.js`.
- Self-host the Vazirmatn font instead of loading it from Google Fonts.
- Split `ui/scorecard.js` into pure layout calculations and canvas rendering.
- CI now uses `npm ci` instead of `npm install`.
- The detective's answer now reads «name» جاسوس است. or «name» شهروند است. (it used to be «name» قطعاً جاسوس است! or «name» شهروند بی‌گناه است.) and is written as plain text. The role card shows the saved sentence exactly as saved, so a game saved before this change still shows its old sentence.
- Every Persian text in the code (about 175 lines in `ui/`, `game/`, `app/`, `core/` and `platform/`: toasts, validation messages, role cards, the result and elimination texts, the details list, the scorecard image, the hand-over gate) now lives in the Persian catalog and is read with `t()` / `tn()` / `tHtml()` / `setTemplate()`. A sentence with a name or a number is one template (`{name}`, `{count}`), never pieces glued together, so another language can reorder it. Nothing changes for players.
- Four sentences that were split over several `<span>`s in `index.html` (the vote confirmation, the spy-guess announcement, "suspect:" and "saved words (n):") are now one element each, filled by JS with one template. The name keeps its bold look.
- **Logical CSS.** `text-align: right` became `text-align: start` in eight rules (the `.text-right` utility is now `.text-start`); the toggle knob, the pass-the-phone icon and the ambient glow drift use `calc(Npx * var(--dir))` instead of a literal sign and the `[dir="rtl"]` toggle override; the podium order is the LTR order by default with a `:root[dir="rtl"]` override, so silver, gold, bronze reads left to right in both directions. In Persian every screen is pixel-identical.
- **Names are isolated from the page direction.** `unicode-bidi: plaintext` on name fields, name cards, the hand-over and role-card titles, `<strong>` and `<option>`; `<bdi>` around names in table cells and headings; `isolate()` around names in plain-text sentences (turn director, "(you)", fellow spies, elimination, tie wheel, wheel labels).
- **The scorecard image follows the language:** `ctx.direction`, the mirrored rows of the "other players" list, one line-level isolate per line (RLI for RTL, the mark the Persian image always used; LRI for LTR) plus one isolate per name, and the date from `formatDate`. The Persian image has the same SHA-256 before and after (same seed, same date, 5 players).

The Persian label is unchanged.

The custom-word list shows the active language's "no hint" text for it, so Persian looks exactly as before. ### Fixed

- **A big tie left players out of the scorecard image.** A podium slot names at most two players ("A and B (tied)"); for three or more it writes "A and N others (tied)", and the other N names were nowhere in the image, because the "other players" list only drew rank 4 and below. (Found in a real 20-player match: players ranked 4th were listed, players tied for 3rd were not.) Now the tied players the slot does not name are the first rows of that list, before the rank 4+ rows (they outrank them), each with its real rank number and the tied marker, so every player is in the image exactly once. This holds for a tie of three or more at 1st, 2nd or 3rd. The podium text, a two-way tie (named as a pair, as before), the ranking itself (dense: 1, 2, 2, 3) and the on-screen leaderboard (which already listed everyone) are unchanged, and so is the image of a game with no tie of three or more at the podium (pixel for pixel, for 3 players, a two-way tie and 20 players with no ties). The list header ("Other players") still reads right for these rows: it means the players the podium does not name, which is what the podium's own "and N others" says.
- The longest list the game can now draw is 19 rows (20 players all tied for 1st), up from 17. It fits the fixed 720x1280 canvas without growing it (scale 0.71 instead of 0.77, names 11px instead of 12px), but the 13px list header sat 1.5px above the first row and touched it. Its baseline now moves up when the band is squeezed (`headerBaselineY`); with 17 rows or fewer it is where it always was.
- **A very long name could run over its neighbours in the scorecard image.** A podium name with no space in it (the line cannot break) was drawn wider than its slot, over the next slot and off the canvas edge; it is now cut with an ellipsis (`wrapCanvasText`). In a game with few players the list rows are drawn large, and a long name ran into the score; the name now stops before the measured score (`computeRestNameMaxWidth`, never wider than the 500px it always had).
- **The first tap on a name input did nothing after the player count had been edited.** The count field's `change` event (fired when it loses focus, which is the moment a name input is tapped) made `renderNameInputs` destroy and recreate every name input, so the tapped element was gone and the keyboard could close. The inputs are now updated in place; a browser test taps with a mouse and with touch and checks that the same element is focused and that a typed name stays.
- **Names in the other script no longer scramble.** A Latin name with punctuation (`Dr. Ali!`) was drawn as `!Dr. Ali` in the Persian scorecard image (every name was forced right-to-left) and could show its punctuation on the wrong side in sentences; names are now isolated by their own first letter. Persian names are drawn as before.
- The default text of the emergency-bell badge in `index.html` now matches what JS writes ("زنگ: نامحدود").
- The "all topics" button on the setup screen promised "+500 words", but the word bank has 741; it now says "+700 words". A test ties the label to the real size of the bank.
- **Correct guess in a one-spy game gave the round to the citizens.** `finalizeRound` checked "no spy left alive" before the forced spy win, and the spy who guessed had just been voted out, so with a single spy the guess paid points but the citizens still won. A correct guess now always gives the spies the round.
- With `spiesCount` at or above the number of players (not reachable from the setup screen), the fool and detective seats were counted from the uncapped spy count, so they went missing. They now follow the spies that were actually assigned.
- The comment on `HIDDEN_TIEBREAK.DEFAULT_MULTIPLIER` said "all"-pool rounds have no multiplier; the default only applies to words with no difficulty rating, such as custom words.
- **Old votes were counted in the next ballot after a time-out.** `votesCast` was only emptied at the start of a round and on the emergency bell, so when the discussion timer ran out (or a saved game whose countdown had already ended was restored) the new ballot still counted the previous ballot's votes, including those of a player who had since been eliminated. That could turn a tie into a win without the wheel and credit `spiesCaught` / `wrongVotes` to a voter no longer in the game. Both time-out paths now start the ballot with no votes; restoring a game saved in the middle of a vote still keeps its partial votes.
- **The detective's answer looked different for a spy and for a citizen, and the role card told them apart by searching the saved text for «جاسوس».** Both answers now have one shape, with no emoji and no colour class, and nothing is decided from the text any more, so translating the interface cannot break it. The name is written with `textContent`, so a name that contains HTML shows as plain text.
- **The floating cover-mode and install buttons used the safe-area inset of the wrong side in the RTL layout.** In Persian the cover-mode button sits on the physical right but read the left inset (and the install button the reverse), so in landscape on a notched phone the notch could cover the button while the other side pushed it away for nothing. Two `:root[dir="rtl"]` overrides now read the inset of the side each button is on. With no inset every value is still `max(16px, 0)`, so the Persian layout is pixel-identical.
- **A match resumed on the round-result screen showed the wrong title and an empty winner box.** `#result-title` and `#result-desc` were written once, by `buildHostRoundResult`, when the round resolved, and were never drawn from the saved state, so after a reload and "Resume match" the screen showed the static Persian default title of `index.html` and nothing under it, also for an English match. One function, `renderRoundResult` in `ui/results.js`, now draws the title (with its colour), the winner box and nothing else, and it runs from both places: `buildHostRoundResult` when the round resolves, and `renderUI` every time the result phase is drawn, the way the round-number line already was. The only thing that was not saved is the outcome, so `gameState.round.result` (`{ winner, reason }`, the same two values the screen shows; `startNextRound` removes it) is stored when the round resolves; the secret word, the player voted out, the tie note, the scores and the language of the match come from what was already saved, and the text comes from the catalog of the saved match's language (`RESTORE_GAME` switches to it before the render). `SAVE_VERSION` stays 12: the field is optional, a save without it (made before this fix) restores as it did and shows no wrong text, and a save with it restored by older code simply ignores it. Nothing hidden during play is stored: the field exists only from the moment the result screen is drawn. `formatRoundResultHtml` moved to `ui/results.js` with its escaping unchanged. Tests: `tests/unit/result-restore.test.mjs` (each ending in both languages, the stored outcome, a real match played to each ending and restored on a page in the other language, old and damaged saves) and `tests/e2e/result-restore.test.mjs` (production build: play to the result, reload, resume, compare the visible text), with the round-playing steps shared in `tests/e2e/helpers/play.mjs`.
- **Custom words ignore the difficulty.** `filterPoolByDifficulty()` (`game/rounds.js`) kept only the words whose `diff` is one of the chosen levels, and every custom word carries the internal rating `medium` (`cleanCustomWord` in `core/storage.js`; the player never picks it), so with "medium" unticked (easy + hard, say) the player's own words silently never came up, unless the filter happened to leave nothing at all. A pool entry with `_cat === 'custom'` now always stays in the pool whatever levels are chosen, so the difficulty chips narrow the built-in words only. The rule is one small, commented predicate, `ignoresDifficulty()`, next to the filter (a custom word that carries an `easy` or `hard` rating from an imported file is ignored by the setting too, because the rule follows `_cat` and not the rating), so a real difficulty choice for custom words later is a change in one place. Unchanged: all three levels leave the pool as it is, used-word tracking, legacy string values (`'all'`, `'easy'`, ...) and garbage, the scoring of custom words (`wordDifficulty` `null`, a correct guess pays 2) and the storage format (`SAVE_VERSION` stays 12). The "no word left, use the unfiltered pool" fallback stays too, but it can no longer happen while the pool holds a custom word (a custom word is always kept, so the filter result is never empty then); it now only covers a pool of built-in words none of which has a chosen rating, which the shipped word banks never produce (every category has words of every level). A pool of only custom words gives the same words as before. Tests: the custom-word cases of `tests/unit/difficulty.test.mjs` that pinned the old behaviour (custom words left out when medium was not chosen) now pin the new one, and new ones cover only easy, only hard, medium + hard and every other combination on both word banks, the filter on its own and through `startNextRound`, a pool of only custom words (also with words that carry different ratings, the case a dropped rule would change), only the custom category ticked, the predicate following `_cat` and not the rating, the fallback with and without a custom word, used-word tracking with custom words in the pool, and legacy `'all'` / `'easy'` / `'medium'` / `'hard'` saves restored with custom words. `tests/e2e/difficulty-chips.test.mjs` (production build, both languages) ticks only "hard" and the events and custom categories with one stored custom word and pins the random source to the last word of the pool: the custom word is the one drawn and the saved round records no rating; with the source pinned to the first word the pick is a hard built-in word, so the built-in words are still filtered. `startMatch` in `tests/e2e/helpers/play.mjs` takes an optional `cats` (the category chips to leave ticked, like `levels`).

## 2.0.0

### Changed

- **Split the 5,000-line single-file app** into `index.html`, `css/style.css`, and 31 ES modules under `js/`. Game behaviour is unchanged; this was verified by playing identical seeded games on the old and new builds and comparing visible text, saved state, computed styles, and the exported scorecard image.
- `gameState` and `hostSecretState` are restored in place (`replaceGameState`, `replaceHostSecrets`) instead of being reassigned; loose UI variables moved into a `session` object; the timer and mute state are owned by `game/timer.js` and `platform/audio.js`.
- Icons moved to `assets/icons/`; the maskable icon is now a separate, padded image.
- The 21 inline `style` attributes in the markup became utility classes; the runtime patch of the "+500 words" label moved into the HTML.
- Removed dead code inherited from the single-file version: `checkWagerCompletion()` was declared but never called.
- Content Security Policy no longer allows inline scripts, and the ineffective `frame-ancestors` directive was removed from the `<meta>` policy.

### Fixed

- **Service worker never invalidated its cache.** The cache name was fixed (`spyfall-v1`) and every request was cache-first, so installed users kept the first version forever. The build now stamps the worker with a content hash, precaches with `cache: 'reload'`, deletes old caches on activate (including the legacy one), and the app announces when an update is ready.
- Cross-origin fonts are cached for offline use after the first online visit.

### Added

- MIT `LICENSE` (the previous README said "all rights reserved").
- GitHub Actions: CI (lint, unit, build, end-to-end) and GitHub Pages deployment.
- `scripts/build.mjs` (integrity checks, hashing, precache list) and `scripts/serve.mjs`.
- 73 unit tests and 3 end-to-end tests; ESLint, Prettier and EditorConfig.
- `docs/architecture.md`, `CONTRIBUTING.md`, Dependabot.
